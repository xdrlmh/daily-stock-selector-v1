# 🎯 主升浪日报 · GitHub Actions 版（钉钉 / 飞书双通道推送）

> 完全云端执行 / 零月费 / 永久免费 — 每交易日 **08:35 推送主升浪精选**、**18:30 推送盘后复盘 + 模拟盘移动止盈/时间止损结算**

## ✨ 项目亮点

- ✅ **完全云端**：GitHub Actions 跑在微软 Azure 云端，电脑关机 100% 不影响
- ✅ **零月费**：GitHub 每月送 2000 分钟 Actions 运行时间，本项目每天只需 1-2 分钟
- ✅ **永久免费**：无过期、无续费、无服务费
- ✅ **双时段推送**：早盘 08:35 选股（今日关注什么）＋ 盘后 18:30 复盘（今天发生了什么 / 持仓怎么办）
- ✅ **模拟盘持仓**：自动跟进头 3 只，**移动止盈**（+15% 启动，峰值回撤 8% 卖出）＋ 固定止损 -7%
- ✅ **时间止损**：清理僵尸股（≥8 交易日且期间最高 <3%）与低效股（≥15 交易日且 <5%），把仓位让给新机会
- ✅ **大盘熔断**：上证指数单日跌幅 ≤2% 时当天**暂停时间止损**（止损/移动止盈照常），避免暴跌日卖在最低点
- ✅ **自动补仓**：止盈/止损/时间止损平仓后，用当日强势股 TOP 自动补齐到 3 只
- ✅ **日期安全**：建仓价归一化只在「行情日 > 信号日」执行，同日重复运行不会污染成本基准
- ✅ **取数自动回退**：Tushare T+1 数据未发布时，自动回退到最近已发布交易日（最多 5 天）
- ✅ **手动触发**：在 GitHub 网页可随时手动跑一次（用于测试）
- ✅ **历史归档**：每次报告自动 commit 到 GitHub 仓库，可追溯
- ✅ **双通道推送**：钉钉 / 飞书群自定义 webhook 机器人，手机端实时收到消息（至少配一个即可）
- ✅ **飞书卡片自适应**：钉钉风格的 markdown 表格自动转成飞书列布局，标题栏 / 主题色按消息类型自动切换

访问 https://github.com/signup 注册免费账号。

### 2. 配置群机器人（钉钉 / 飞书，至少选一个）

#### 方案 A：钉钉

1. 手机打开 **钉钉** → 进入您已建好的群
2. 右上角 **「···」→「群机器人」→「添加」→「自定义」**
3. 机器人名：`主升浪日报`
4. **安全设置** 推荐选 **「加签」**（更安全）：
   - 勾选「加签」后会自动生成一个密钥（`SEC...` 开头），**复制下来**
   - 如果您不方便复制加签，可选 **「自定义关键词」** 并填 **`主升浪`**（推送内容里必须包含这个词）
5. 勾选协议 → **复制 webhook URL**（形如 `https://oapi.dingtalk.com/robot/send?access_token=xxx`）

> 💡 **加签 vs 自定义关键词**：
> - 加签（推荐）：webhook URL + 时间戳 + 签名验证，最安全
> - 自定义关键词：内容里必须出现「主升浪」三个字，否则推送失败
> - 二选一即可，本项目两种模式都支持

#### 方案 B：飞书

1. 打开 **飞书** → 进入您已建好的群
2. **「···」→「设置」→「群机器人」→「添加机器人」→「自定义机器人」**
3. 机器人名：`主升浪日报`
4. **安全设置** 勾选 **「签名校验」**（推荐），把生成的密钥**复制下来**
5. 复制 **webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx`）

> 💡 **飞书与钉钉的差异（本项目已全部自动处理，无需操心）**：
> - 飞书签名用**秒级**时间戳且放在**请求体**里（钉钉是毫秒级 + 拼在 URL 上）
> - 飞书卡片**不支持 markdown 表格** → 榜单会自动转成**飞书列布局**，视觉上仍是横向表格
> - 卡片按消息类型自动换主题色：早盘蓝 / 复盘青 / 盘中告警红
> - 消息过长时自动分片，不会因为超限而发送失败

## 🚀 部署步骤（10 分钟）

### 第 1 步：上传代码到您自己的 GitHub 仓库

1. 在 GitHub 网页 **「New repository」** 创建新仓库，例如 `daily-stock-selector`
2. 把本目录的 **所有文件** 上传（拖拽到网页即可）
3. ⚠️ 路径必须保留 `.github/workflows/daily.yml`（GitHub 才能识别为 workflow）

### 第 2 步：配置 Secrets

进入您创建的仓库页面：
1. **Settings** → **Secrets and variables** → **Actions**
2. 点 **「New repository secret」** 添加：

| Secret 名 | 值 | 必填 |
|---|---|---|
| `DINGTALK_WEBHOOK` | 钉钉 webhook URL | 二选一 |
| `DINGTALK_SECRET` | 钉钉加签密钥（`SEC...`）| ⚠️ 可选 |
| `FEISHU_WEBHOOK` | 飞书 webhook URL | 二选一 |
| `FEISHU_SECRET` | 飞书签名密钥 | ⚠️ 可选 |

> ⚠️ **钉钉 / 飞书至少要配一个**；两个都配 = **双通道并行推送**。
> - 选了「加签 / 签名校验」模式的，对应的 `*_SECRET` 必须填；关键词模式可不填
> - 未配置 webhook 的通道会被**自动跳过**，不会导致推送失败
> - 想只推一个通道：在 workflow 的 `env` 里加 `PUSH_CHANNELS: dingtalk`（或 `feishu`）

### 第 3 步：启用 Actions

1. 进入仓库 **Actions** 页面
2. 如果看到「Workflows aren't being run on this forked repository」提示，点 **「I understand my workflows, go ahead and enable them」**

### 第 4 步：手动测试一次（不实际推送）

1. 进入 **Actions** → 左侧选 **「主升浪精选日报」**
2. 右侧点 **「Run workflow」** → 默认勾选 **「仅测试，不实际推送」** → 点绿色按钮
3. 等待 1-2 分钟，看运行日志（应该是 ✅ 成功，但不真正推送）

### 第 5 步：正式推送测试

重复第 4 步，但**取消勾选**「仅测试」，真正推送一次。
**打开钉钉 / 飞书群，看是否收到主升浪日报消息。**

## ⏰ 触发时间说明

GitHub Actions 的 cron 使用 **UTC 时间**（协调世界时）。

```
北京时间 = UTC + 8 小时
08:35 北京时间 = 00:35 UTC   → 主升浪精选日报（daily.yml）
18:30 北京时间 = 10:30 UTC   → 盘后复盘 + 持仓结算（review.yml）
```

- `daily.yml`：`cron: '35 0 * * 1-5'`（周一至周五 08:35 选股，并把 TOP 3 写入持仓池）
- `review.yml`：`cron: '30 10 * * 1-5'`（周一至周五 18:30 复盘，结算持仓 + 自动补仓）
- `monitor.yml`：**已取消定时**，仅保留手动触发（盘中应急/调试用；常规止盈止损已并入复盘）

> ⚠️ **注意**：GitHub 的 cron 调度通常有 5-30 分钟延迟（不是精确到分钟）。这是 GitHub 平台的限制，不是本项目的问题。
>
> 💡 Tushare 行情数据为 **T+1**（当日 17:00-19:00 发布）。因此 08:35 早盘任务会**自动使用前一交易日数据**，这是设计行为，不是故障。

## 💼 模拟盘持仓规则

系统按五维评分买进 **头 3 只**，形成模拟盘组合：

| 规则 | 参数 | 说明 |
|---|---|---|
| 最大持仓 | 3 只 | 满仓不再补仓 |
| 买入价 | 信号次日**开盘价** | 贴近模拟盘真实成本（仅当行情日 > 信号日才归一化，避免同日重复运行污染成本） |
| 止损 | **-7%**（固定） | 收盘盈亏 ≤ -7% 平仓 |
| 移动止盈 | **+15% 启动 / 回撤 8% 卖出** | 盈利首次 ≥ +15% 启动，随后跟踪最高价，跌回撤线即卖出 |
| 时间止损 | **僵尸 8 日 / 低效 15 日** | 长期不走出趋势 → 清仓让位（详见下节） |
| 大盘熔断 | **上证单日 ≤ -2%** | 当天暂停时间止损（止损/移动止盈不受影响），避免暴跌日被批量扫出 |
| 自动补仓 | 平仓后补齐至 3 只 | 用当日强势股 TOP 补位，当日刚平仓/刚清理的票不回补 |

**移动止盈细则**：

1. **启动**：持有期盈利（按盘中最高价）首次 ≥ **+15%** → 移动止盈启动
2. **峰值**：启动后记录最高价 `trail_high`（盘中最高价与收盘价取大，**只上不下**）
3. **卖出**：盘中最低价 ≤ `trail_high × (1 - 8%)` → 视为触发，按**触发线价格**成交
4. 峰值越高，回撤线越高 → 锁住利润，同时不切断趋势（区别于固定 +15% 到点就卖）

> 📐 **参数口径示例**（买入 10 元）：峰值 11.50 → 回撤线 10.58（锁 +5.8%）；峰值 13.20 → 回撤线 12.14（锁 +21.4%）。
> 想让锁利更激进可把 `TRAIL_DRAWDOWN_PCT` 调小（3），想拿更久可调大（10）。

> 举例：买入 10 元 → 涨到 15 元（+50%，峰值）→ 回撤线抬到 13.80 元 → 跌破 13.80 元卖出，锁定约 **+38.0%**；
> 若只涨到 11.5 元（+15%）就回落 → 回撤线 10.58 元 → 跌破即卖出，锁定约 **+5.8%**。

**时间止损细则**（清理僵尸股 / 低效股，让仓位流动起来）：

| 类型 | 触发条件 | 动作 |
|---|---|---|
| 🧟 **僵尸股** | 持有 ≥ **8 个交易日** 且 期间最高涨幅 < **3%** | 清仓 |
| 🐌 **低效股** | 持有 ≥ **15 个交易日** 且 未启动移动止盈 且 期间最高涨幅 < **5%** | 清仓 |
| 🔒 豁免 | 已启动移动止盈的持仓 | 永不清（趋势已确认，交给移动止盈） |

1. **交易日钟 `days_held`**：每遇到一个**新的行情日** +1 —— 同日重复运行不重复计数，周末/节假日自动跳过，无需额外接口
2. **判定口径 `peak_high_pnl`**：用持有期内的**最高价**算峰值（只上不下），比看当前盈亏公平——单日普跌不会把形态尚可的票误杀
3. **触发优先级**：止损 -7% ＞ 移动止盈 ＞ **时间止损** ＞ 接近启动线提醒
4. 清理腾出的仓位与止盈止损一样，**当晚 18:30 复盘立刻用当日强势股补齐**
5. 参数集中在 `src/portfolio.py` 顶部：`ZOMBIE_DAYS` / `ZOMBIE_PEAK_PCT` / `INEFFICIENT_DAYS` / `INEFFICIENT_PEAK_PCT`（`TIME_STOP_ENABLED=False` 可整体关闭）

> 🧟 举例：某票 10 元建仓，持有 8 个交易日期间最高只到 10.25（+2.5%）→ 判定僵尸股 → 清仓换股。
> 🐌 举例：某票 20 元建仓，持有 15 个交易日期间最高只到 20.90（+4.5%）→ 判定低效股 → 清仓换股。

**⚡ 大盘弱势熔断**（2026-09-11 新增，避免暴跌日卖在最低点）：

| 类型 | 触发条件 | 动作 |
|---|---|---|
| ⚡ 熔断 | 上证指数**单日跌幅 ≤ -2%** | 当天**暂停时间止损**，持仓不动 |
| 🚨 不受影响 | 止损 -7% / 移动止盈 | **照常执行**（硬纪律，不因大盘弱而放宽） |
| 🔁 恢复 | 次日大盘企稳 | 条件仍满足 → **自动补执行**清理 |

- 熔断只拦「主动换仓」（清理僵尸/低效股），不拦「保护性出场」，两者互不干扰
- 熔断当天**考察期照常计时**（days_held 继续 +1），只是不执行卖出，次日企稳即补执行
- 取数失败（指数涨跌幅为空）时**不熔断**，避免因数据问题导致清理长期停摆
- 时间止损**只在盘后复盘执行**（盘中监控仅告警）—— 这样清仓后能立刻用当日强势股补位，不会半天空仓
- 参数：`src/portfolio.py` 顶部 `MARKET_FUSE_ENABLED` / `MARKET_FUSE_DROP_PCT` / `MARKET_FUSE_INDEX`

## 🔧 常见问题

### Q1：推送没有准时到达？
GitHub Actions 的 cron 有时延迟 10-30 分钟，属于平台特性。如需精确到分钟，需升级到 GitHub Pro。

### Q2：钉钉群里没收到推送？
1. **检查 Secret 是否填对**：`DINGTALK_WEBHOOK` 必须以 `https://oapi.dingtalk.com/robot/send?access_token=` 开头
2. **加签模式**：检查 `DINGTALK_SECRET` 是否填了（必须以 `SEC` 开头）
3. **自定义关键词模式**：推送内容里必须出现「主升浪」三个字（默认已包含）
4. 看 GitHub Actions 日志，是否有 `推送失败` 字样 + 错误详情

### Q2b：飞书群里没收到推送？
1. **检查 webhook**：`FEISHU_WEBHOOK` 必须以 `https://open.feishu.cn/open-apis/bot/v2/hook/` 开头
2. **签名校验模式**：检查 `FEISHU_SECRET` 是否填了（在机器人「安全设置 → 签名校验」里复制）
3. **只在钉钉收到、飞书没收到**：说明飞书单独失败（双通道互不影响），日志里会有 `❌feishu` 标记和具体原因
4. 日志出现 `19021 sign match fail` → 密钥填错，或服务器时间偏差超过 1 小时

### Q2c：飞书消息里的表格显示成竖线堆叠？
飞书卡片**原生不支持 markdown 表格**，本项目会自动转成**列布局（column_set）**。
若仍看到竖线堆叠，说明自动转换没生效——请确认推送的是 `src/feishu.py`（而不是旧版直发 markdown）。

### Q3：钉钉返回 "keywords not in content" 错误？
您选择了「自定义关键词」模式但没填「主升浪」。两种解法：
- 群机器人设置里把关键词改为「主升浪」
- 改用「加签」模式（更安全）

### Q4：钉钉返回 "sign not match" 错误？
您开启了加签但 `DINGTALK_SECRET` 没填或填错。检查 Secret 值是否以 `SEC` 开头且完整。

### Q5：如何修改推送时间？
编辑 `.github/workflows/daily.yml`，调整 cron 表达式。例如改为早上 9:00 北京时间：
```yaml
- cron: '0 1 * * 1-5'  # UTC 01:00 = 北京时间 09:00
```

### Q6：如何修改主题关键词？
编辑 `src/selector.py` 中的 `HOT_THEMES` 字典，添加您关注的题材关键词。

### Q7：如何更换评分权重？
编辑 `src/config.py` 中的 `SCORE_WEIGHTS`，合计必须为 100。

### Q8：数据抓取失败？
本项目已改用 **Tushare Pro**（akshare 在云端 IP 会被东财限流，已弃用）。若失败：
1. 检查 `TUSHARE_TOKEN` 是否已配置、积分是否够用
2. 看 GitHub Actions 日志里的具体错误
3. Tushare 日线数据约 **17:00-19:00** 才更新，早盘任务会自动回退到最近已发布交易日（最多回退 5 天）
